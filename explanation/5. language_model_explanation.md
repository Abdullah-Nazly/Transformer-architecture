# Complete Explanation: Language Model (lm.py and transformer_lm.py)

## Overview

The language model task is different from letter-counting. Instead of classifying at each position, it **predicts the next character** given a context. This is an **autoregressive** task where the model learns to generate text character by character.

---

## Two Model Types: UNIFORM vs NEURAL

### UNIFORM Model

- **Simple baseline**: Assigns equal probability to all characters
- **No training required**: Just returns uniform distribution
- **Baseline for comparison**: Shows what random guessing looks like

### NEURAL Model

- **Trained transformer**: Learns character probabilities from data
- **Requires training**: Trains on text data to learn patterns
- **Actual language model**: Can predict likely next characters

## UNIFORM Model: Detailed Explanation

### What It Is

```python
class UniformLanguageModel(LanguageModel):
    def __init__(self, voc_size):
        self.voc_size = voc_size  # 27
```

**Simple baseline model** that assigns equal probability to all characters.

### How It Works

#### Method 1: `get_next_char_log_probs(context)` (line 46-47)

```python
def get_next_char_log_probs(self, context):
    return np.ones([self.voc_size]) * np.log(1.0 / self.voc_size)
```

**What it does:**

- Ignores the context completely
- Returns uniform distribution: `log(1/27)` for all 27 characters
- Every character has the same probability: `1/27 ≈ 0.037`

**Example:**

```python
# Context: "hello worl"
# UNIFORM model returns:
log_probs = [-3.296, -3.296, -3.296, ..., -3.296]  # 27 values, all the same
# Each character has log probability = log(1/27) = -3.296
# This means: P('a' | "hello worl") = P('b' | "hello worl") = ... = P('z' | "hello worl") = 1/27
```

**Key point:** Context doesn't matter! The model treats all characters equally regardless of what came before.

#### Method 2: `get_log_prob_sequence(next_chars, context)` (line 49-50)

```python
def get_log_prob_sequence(self, next_chars, context):
    return np.log(1.0 / self.voc_size) * len(next_chars)
```

**What it does:**

- Computes log probability of a sequence of characters
- Formula: `log(1/27) × length`
- Each character contributes `log(1/27)` to the total

**Example:**

```python
# Context: "hello "
# Next chars: "world"
# Length: 5

log_prob = log(1/27) × 5 = -3.296 × 5 = -16.48

# This means:
# P("world" | "hello ") = (1/27)^5 = very small probability
```

**Why it's a baseline:**

- Shows what random guessing looks like
- Any trained model should perform better than this
- Useful for comparison: if your model is worse than uniform, something is wrong!

```python
# Input text: "hello world"

train_tensor = [7, 4, 11, 11, 14, 26, 22, 14, 17, 11, 3]

```

**Shape:** `[num_characters]` - one long sequence

---

### Step 2: Create Training Chunks (transformer_lm.py lines 130-150)

**The Problem:**

- Text is one long sequence (could be 100,000+ characters)
- Transformer can only process fixed-length sequences (e.g., 256 characters)
- Need to split into chunks

**The Solution: `make_chunks()` function:**

```python
def make_chunks(text_tensor, seq_len, stride=None):
    if stride is None:
        stride = seq_len  # No overlap by default
    inputs, targets = [], []

    if len(text_tensor) <= seq_len:
        # Handle short sequences (padding)
        pad_len = max(0, seq_len - len(text_tensor) + 1)
        padded = torch.cat([text_tensor, torch.zeros(pad_len, dtype=torch.long)])
        inputs.append(padded[:seq_len])
        targets.append(padded[1 : seq_len + 1])
    else:
        # Split into overlapping chunks
        for i in range(0, len(text_tensor) - seq_len, stride):
            inputs.append(text_tensor[i : i + seq_len])
            targets.append(text_tensor[i + 1 : i + seq_len + 1])

    return torch.stack(inputs), torch.stack(targets)
```

**What this does:**

- Splits long text into fixed-length chunks
- Creates input-target pairs for training
- **Target is input shifted by 1 position** (predict next character)

**Example with seq_len=10, stride=5:**

```python
# Original text tensor: [7, 4, 11, 11, 14, 26, 22, 14, 17, 11, 3, 26, ...]
# "hello world ..."

# Chunk 1:
inputs[0]  = [7, 4, 11, 11, 14, 26, 22, 14, 17, 11]  # "hello worl"
targets[0] = [4, 11, 11, 14, 26, 22, 14, 17, 11, 3]  # "ello world"

# Chunk 2 (stride=5, so starts at position 5):
inputs[1]  = [26, 22, 14, 17, 11, 3, 26, ...]  # " world ..."
targets[1] = [22, 14, 17, 11, 3, 26, ...]     # "world ..."

# Chunk 3 (starts at position 10):
inputs[2]  = [...]
targets[2] = [...]
```

**Key insight:**

- **Input**: Characters at positions 0 to seq_len-1
- **Target**: Characters at positions 1 to seq_len (shifted by 1)
- **Purpose**: Model learns to predict character at position i+1 given characters 0 to i

**Stride (overlap):**

- `stride = seq_len`: No overlap (chunks don't share characters)
- `stride < seq_len`: Overlap (chunks share characters, more training data)

**Example with overlap (stride=5, seq_len=10):**

```
Chunk 1: positions 0-9
Chunk 2: positions 5-14  (overlaps with chunk 1 at positions 5-9)
Chunk 3: positions 10-19 (overlaps with chunk 2 at positions 10-14)
```

**Why overlap?**

- Creates more training examples from same data
- Especially useful for small datasets
- Helps model see more context variations

**Stride selection (line 153):**

```python
chunk_stride = seq_len // 8 if len(train_tensor) < 200000 else seq_len // 4
```

- **Small dataset** (< 200k chars): `stride = seq_len // 8` (more overlap, more examples)
- **Large dataset** (≥ 200k chars): `stride = seq_len // 4` (less overlap, still plenty of data)

---

### Step 3: Training Data Structure

**After `make_chunks()`:**

```python
train_inputs:  [num_chunks, seq_len]  # e.g., [1000, 256]
train_targets: [num_chunks, seq_len]  # e.g., [1000, 256]
```

**Example:**

```python
# If we have 100,000 characters and seq_len=256, stride=64:
# Number of chunks = (100000 - 256) / 64 + 1 ≈ 1,560 chunks

train_inputs.shape  = [1560, 256]  # 1,560 chunks, each 256 chars
train_targets.shape = [1560, 256]  # 1,560 targets, each 256 chars

# Each row is one training example:
train_inputs[0]  = [7, 4, 11, 11, 14, ..., 26]  # First 256 chars
train_targets[0] = [4, 11, 11, 14, 26, ..., 22] # Next 256 chars (shifted)
```

**Training objective:**

- Given `train_inputs[i]`, predict `train_targets[i]`
- For each position j: predict `targets[i][j]` given `inputs[i][0:j+1]`
- This is **autoregressive**: predict next character given previous characters

## Key Differences: UNIFORM vs NEURAL

### UNIFORM Model

**Characteristics:**

- ✅ **No training**: Instant, no computation needed
- ✅ **Simple**: Just returns uniform distribution
- ✅ **Baseline**: Shows random guessing performance
- ❌ **No learning**: Doesn't use context at all
- ❌ **Poor performance**: All characters equally likely

**Use cases:**

- Baseline for comparison
- Testing evaluation code
- Understanding what "random" looks like

**Example output:**

```python
context = "hello worl"
# UNIFORM always returns:
log_probs = [-3.296, -3.296, -3.296, ..., -3.296]  # All same
# P('d' | "hello worl") = P('x' | "hello worl") = 1/27
```

---

### NEURAL Model

**Characteristics:**

- ✅ **Trained**: Learns from data
- ✅ **Context-aware**: Uses previous characters to predict next
- ✅ **Better performance**: Can learn patterns in text
- ❌ **Requires training**: Takes time and computation
- ❌ **Complex**: Transformer architecture

**Use cases:**

- Actual language modeling
- Text generation
- Learning character-level patterns

**Example output:**

```python
context = "hello worl"
# NEURAL (after training) might return:
log_probs = [-5.2, -4.1, -3.8, ..., -2.1, ..., -6.5]
#                          ↑                    ↑
#                    'd' is likely        'x' is unlikely
# P('d' | "hello worl") > P('x' | "hello worl")
# Model learned that 'd' is more likely after "hello worl"
```

## Data Flow Comparison

### UNIFORM Model Flow

```
Input: context = "hello worl"
       ↓
UniformLanguageModel.get_next_char_log_probs()
       ↓
Return: [log(1/27), log(1/27), ..., log(1/27)]  # 27 values, all same
       ↓
Output: Uniform distribution (no learning)
```

**No data preparation needed!** Just instantiate and use.

---

### NEURAL Model Flow

```
1. Read text files
   train_text = "hello world the quick..."
   ↓
2. Convert to indices
   train_tensor = [7, 4, 11, 11, 14, 26, ...]
   ↓
3. Create chunks
   train_inputs = [[7, 4, 11, ...], [26, 22, 14, ...], ...]
   train_targets = [[4, 11, 11, ...], [22, 14, 17, ...], ...]
   ↓
4. Train transformer model
   (learns to predict next character)
   ↓
5. Use trained model
   context = "hello worl"
   → model predicts next character probabilities
```

**Extensive data preparation and training required!**

## Training Process (NEURAL Model)

### Model Configuration

```python
model = Transformer(
    vocab_size=27,              # 26 letters + space
    num_positions=256,          # Sequence length (longer than letter-counting!)
    d_model=128,
    d_internal=256,
    num_classes=27,             # Predict one of 27 characters
    num_layers=3,               # 3 transformer layers
    use_positional_encoding=True,
    use_causal_mask=True,       # CRITICAL: Must use causal mask!
    batched_pe=True,
    num_heads=4,                # Multi-head attention
).to(device)
```

**Key differences from letter-counting:**

- `num_classes=27` (not 3): Predicts which character comes next
- `num_positions=256` (not 20): Longer sequences
- `use_causal_mask=True`: Must prevent looking at future
- `num_heads=4`: Multi-head attention (not single-head)

### Training Objective

**For each chunk:**

- **Input**: Characters at positions 0 to 255
- **Target**: Characters at positions 1 to 256 (shifted by 1)
- **Goal**: Predict character at position i+1 given characters 0 to i

**Loss function:**

```python
loss = NLLLoss(log_probs.view(-1, vocab_size), targets.view(-1))
```

- `log_probs`: `[batch, seq_len, vocab_size]` → `[batch*seq_len, vocab_size]`
- `targets`: `[batch, seq_len]` → `[batch*seq_len]`
- Computes negative log likelihood for each position

## Summary: UNIFORM vs NEURAL

| Aspect            | UNIFORM             | NEURAL                   |
| ----------------- | ------------------- | ------------------------ |
| **Training**      | None                | Required (6 epochs)      |
| **Data Prep**     | Minimal             | Extensive (chunking)     |
| **Context Usage** | Ignores context     | Uses context             |
| **Performance**   | Baseline (random)   | Learns patterns          |
| **Speed**         | Instant             | Slow (training)          |
| **Complexity**    | Simple              | Complex (transformer)    |
| **Use Case**      | Baseline comparison | Actual language modeling |

## Key Takeaways

1. **UNIFORM**: Simple baseline that assigns equal probability to all characters
2. **NEURAL**: Trained transformer that learns character probabilities from data
3. **Data preparation**: NEURAL requires chunking long text into fixed-length sequences
4. **Autoregressive**: Both models predict next character given context
5. **Causal masking**: NEURAL must use causal mask (can't see future)
6. **Training chunks**: Created with overlap to maximize training data
7. **Target shift**: Targets are inputs shifted by 1 position (predict next)
